## 官方也建议的省法（2026-11-15 核对官方成本文档 code.claude.com/docs/en/costs 等；价格与默认值以官方当前页为准）

1. **管理上下文：** 换任务用 `/clear`，同一任务用 `/compact`（可带「保留哪些内容」的指令）。注意 `/compact` 本身要读整段上下文，是一次大请求，别拖到最后才用。
2. **缓存按模型各存一份：** 中途切换模型，整段历史要重新计算；缓存有存活期（API 默认约 5 分钟，另有 1 小时选项；订阅账号的主对话默认可能更长，以官方为准），隔久再回来第一轮会重算。所以开窗口时就选对模型，一件事连续做完。
3. **每个会话都载入的东西，长度就是成本：** 全局规则文件、记忆、技能说明。官方建议规则文件控制在 200 行内，专项细则挪进按需载入的技能。（MCP 工具定义默认延迟加载，只有名称进上下文；不用的 MCP 服务仍建议停用。）
4. **输出单价约为输入的 5 倍（官方定价页）：** 要求「结论先说、不超过 N 字、不复述问题」。思考 token 按输出计费，简单任务可用 `/effort` 降低思考强度。
5. **复杂任务先用 Plan 模式：** 官方称它能避免方向错误导致的昂贵返工；发现跑偏，尽早按 Esc 打断或用 `/rewind` 回退，并给出可验证的目标、增量测试。
6. **选对模型：** 日常用中档（Sonnet），最强档留给复杂判断，简单子任务指定小档（Haiku）。（「小模型先筛、大模型后精读」的流水线，官方没有专门推荐，是经验做法。）
7. **把冗长操作交给子智能体，只收摘要：** 子智能体在自己的上下文里干活，只返回摘要；但它自己的请求仍计入用量，所以要限定它回传的字数。官方还提醒：多智能体团队约耗 7 倍 token，慎开。
8. **用 `/usage`、`/context` 看消耗：** 先看清钱花在哪，再决定砍哪里；后台还有会话回顾、闲置压缩、定时任务等持续消耗，闲置时关掉不用的。
9. **提示词写具体：** 模糊的指令会让它多轮摸索；说清对象、范围、验收。
10. **Batch API（直接调 API 的用户）：** 官方定价页写明输入和输出均为 5 折，异步处理、可与缓存叠加；订阅用户用不到。
