## 三、预测大用量任务（派活前 1 分钟）

两条线自己定：「提醒线」只告知不等批准，「确认线」先交方案再做。下表以 50 万、100 万为例。

**估算（【经验规则】经验公式，系数需按你自己的数据校准）：** 预计 token ≈ 读入字数 ×2 ＋ 预计输出字数 ×4 ＋ 预计轮数 × 当前上下文 token。最后一项最容易漏：长会话里每多一轮，都要把整段上下文重读一遍。

| 估算 | 做法 |
|---|---|
| < 10 万 | 直接派，写预估 |
| 10 万到「提醒线」 | 拆成并行块，每块写预估；先让便宜模型抽事实包 |
| ≥ 提醒线（例：50 万） | 派之前先告诉使用者做什么、预估多少，不必等批准 |
| ≥ 确认线（例：100 万） | 先交一页方案（为什么要这么多、先做样品、分几批），使用者确认后再分批派 |

- 每个 agent 派活时写明 token **预估**。预估不是硬停线：超了让它做完，回传时写实际用量和超出原因；不设单个 agent 的硬停线。半路强停常常交回一份没法接着用的半成品，再派新 agent 接手要重读全部上下文，反而更贵。真正要叫停的是「空转」：同一动作失败第 3 次、30 分钟没有进展。派活说明里不要写「用到 N 万就停」。
- **修复类任务怎么估（【经验规则】，系数按你自己的数据校准）：** 底数 5 万 ＋ 每条失败 2 万 ＋ 每个涉及文件 1 万，再乘 1.5；超过提醒线就拆成几个并行任务，并先告诉使用者。让它每修好一条就提交一次，进度不会丢。
- **事后校准（【经验规则】）：** 记「预估 vs 实际」，连续 3 次偏差超 2 倍就调公式系数。
- 常见大头：整包读大量会话记录、多轮最强模型评审、全量测试、批量取数、长文档加多轮评审。
