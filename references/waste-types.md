## 八类浪费对照（找用量漏在哪）

| 浪费 | 在 Claude Code 里的样子 | 怎么发现 | 对策（照着说） |
|---|---|---|---|
| 过度生产 | 需求没确认就开工；多做了没人要的版本 | 交付物用不上 | 「需求确认前先不要开发」；先出 1 件样品 |
| 等待 | 等用户拍板、等授权、后台空跑、反复查状态 | 任务长时间没有新结果 | 要决定的事用选择题问；写明卡在谁；停止轮询 |
| 搬运 | 大文件整包贴进对话；同一材料在多个子智能体之间来回传 | 同一份材料出现 2 次 | 直接读本地文件，只传摘要 |
| 过度加工 | 只要削皮却切成果盘：反复润色、多轮评审 | 评审到第 3 轮 | 写清「做到什么程度就停」，先给能用的 |
| 库存 | 对话越拉越长、每轮重读；旧版本、中间文件堆着没人用 | 上下文超过约 5 万 token | 上下文大了写交接摘要，开新会话；换任务 `/clear` |
| 多余动作 | 同一文件读多遍；盲猜网址试探；简单活用最贵模型（子智能体不写 model） | 一次提问工具循环超过 5 次 | 先读目录；能写脚本就写脚本；按活选模型 |
| 返工 | 方向错了重做；批量整批返工；同一错犯两次 | 同一类错出现第 2 次 | 先出样品；把错误写成规则 |
| 经验没用起来 | 好做法没沉淀，每次重新教 | 同一句话说了 3 遍 | 写进 CLAUDE.md、技能或钩子，开工先读 |

「怎么发现」列的数字是经验阈值，按自己的实测调整。


## 先看钱花在哪

【经验规则】最大的三笔浪费是（作者单一环境的使用记录归纳，样本小，未做对照实验）：

| 浪费 | 怎么做 |
|---|---|
| 会话跨 8 个以上不同小时 | 一个会话只做一件事、不跨天；超过 4 小时写交接摘要，开新会话。长对话每一轮都重读全部上下文，这是最大的一笔 |
| 换任务不 `/clear` | 换任务前把状态记到文件，再 `/clear` |
| general-purpose 子智能体占比高 | 派活时显式写 `model`；有专用 agent 的活用专用的（见第二节） |

你自己的占比请用第七节的复盘方法自查，别套别人的数字。（这三条是经验总结，不是官方固定清单。）
