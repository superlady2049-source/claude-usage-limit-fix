## 〇之二、七类浪费对照（找用量漏在哪）

| 浪费 | 在用量上的样子 | 对策 |
|---|---|---|
| 过度生产（做了没人要的） | 需求没问清就开工，方向错 | 第〇节：先问清、先出最小样本 |
| 等待 | 轮询外部条件、任务空转 | 停掉轮询，写明卡在谁 |
| 搬运 | 把整包原文传给贵模型或子智能体 | 先抽 6,000 字事实包 |
| 过度加工 | 多轮评审、反复润色 | 内部方案评一轮；脚本能判的人不再看 |
| 库存（积压） | 长会话堆积上下文，每轮重读 | 超 4 小时交接，换任务 `/clear` |
| 动作浪费 | 同一份材料读多遍、同一数据取多次 | 读一次，存成要点文件 |
| 缺陷返工 | 同一类错出现第二次 | 做成规则或钩子 |


## 先看钱花在哪

【经验规则】最大的三笔浪费是（作者单一环境的使用记录归纳，样本小，未做对照实验）：

| 浪费 | 怎么做 |
|---|---|
| 会话跨 8 个以上不同小时 | 一个会话只做一件事、不跨天；超过 4 小时写交接摘要，开新会话。长对话每一轮都重读全部上下文，这是最大的一笔 |
| 换任务不 `/clear` | 换任务前把状态记到文件，再 `/clear` |
| general-purpose 子智能体占比高 | 派活时显式写 `model`；有专用 agent 的活用专用的（见第二节） |

你自己的占比请用第七节的复盘方法自查，别套别人的数字。（这三条是经验总结，不是官方固定清单。）
